CRM Bridge / How it works

One contact. One card. Moves left to right.

When a real lead touches LFG, a single contact card lands in your existing LFG Community pipeline and travels through the stages as they progress. No data entry, no duplicates, no clutter.

Step 1
Run RSVP

Card lands in "Warm (Replied)". Tags: new contact, runclub.

Step 2
Bootcamp purchase

Same card moves to "Hot (Interested)". Value shows AED paid. Adds tag bootcamp.

Step 3
Sunday attended

Card moves to "Attended Bootcamp". Value preserved.

Future
Coaching prospect

Reserved stage. Move manually when ready to upsell coaching.

What gets populated, automatically

Contact fields

First name, last name, email, phone (E.164), country = AE, source = exact LFG touchpoint, your existing tags.

Custom fields

"What is your level?" → Beginner / Occasional / Advanced. "How did you hear about us?" → free-text from the registration form.

Opportunity

Named "LFG: <email>". That prefix is our marker, so the integration can identify and update only opps it created. Yours stay untouched.

Monetary value

0 on free run RSVP, package AED on bootcamp purchase, preserved through subsequent stage moves.

Honest accounting

What's not done yet.

Short list. None of it blocks your walk-through or the live launch. Each is a small, deliberate next step.

  • Resend email domain. Booking confirmations and referral reward emails currently send from Resend's sandbox sender. Verifying lfgdubai.com in Resend (4 DNS records into GoDaddy, about 10 minutes) flips the sender to info@lfgdubai.com.
  • Stripe live keys. Test mode is wired and working. Promote to live by swapping the keys at cutover and pointing the production webhook URL at the live domain.
  • Run attendance tracking. Sunday bootcamp attendance is fully tracked. Wed / Sat runs currently only capture RSVPs, not show-ups. Adding run attendance is a focused half-day sprint when you want runs to count toward streaks.
  • Embedded GHL views. The bridge pushes data into GHL. You read it in GHL where your pipeline already lives. If you later want the pipeline and inbox embedded inside the LFG admin, that's a focused sprint we can scope when you're ready.
  • Friday roster cron. The roster email endpoint exists, secured, and ready. Wiring a scheduled cron (GitHub Actions or Vercel Cron) so Friday's roster sends itself takes about 15 minutes after the cron token is finalized.
  • Production deploy. Everything above lives on the preview link. One Vercel deploy to push it to lfgdubai.com, then promote-to-production for zero additional deploy cost.

Nothing on this list is a defect. Each item is a deliberate switch left for you to flip at the right moment.
